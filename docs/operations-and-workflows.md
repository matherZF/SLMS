# 业务流程与审批规则

## 统一审批业务

流程定义采用版本发布机制。每次保存配置都会生成新的版本号并停用旧版本；已发起单据继续引用发起时的流程定义和节点，新版本只影响之后提交的业务。

| 业务编码 | 显示名称 | 审批完成后的动作 |
| --- | --- | --- |
| OUTBOUND | 领用申请 | 进入待拣货状态 |
| RETURN | 退库确认 | 增加原库位原批次库存，更新可退数量和使用台账 |
| SCRAP | 报废申请 | 扣减指定库存并生成 SCRAP 流水 |
| STOCKTAKE_DIFF | 盘点差异复核 | 按实盘数量调整库存并生成 ADJUST 流水 |

## 库存占用与一致性

- 领用审批通过时库存不变；点击“开始拣货”后，系统锁定所选库存记录并增加拣货占用量。
- 页面统一区分实存数量、拣货占用和可用数量，其中 `可用数量 = 实存数量 - 拣货占用`。
- 确认出库时，在同一事务内释放占用并扣减实存；重复确认返回原完成结果，不会再次扣库。
- 拣货中的领用单可以取消，取消时释放全部占用并关闭相应货位灯。
- 报废和移库只能处理可用数量；盘点后的实存数量不得低于仍有效的拣货占用量。
- 占用、扣减和释放均使用数据库行锁，避免多张领用单并发超卖。

## 待办与预警

- 审批节点默认处理时限为 24 小时，可通过环境变量 `APPROVAL_TIMEOUT_HOURS` 调整。
- 超过处理期限不会自动审批或自动驳回，而是在审批中心和当前审批人的工作台标红提醒。
- 库存不足按可用库存计算，避免已经被拣货占用的数量仍被视为可用库存。
- 有实存的批次在到期前 30 天进入临期提醒；当天到期或已经过期时按高级别显示。
- 备件寿命提醒继续以使用台账中的运行小时、任务数或自然日寿命进度为依据。

## 领用条件审批

领用流程支持三种触发模式：始终审批、任一条件满足、全部条件满足。条件可组合备件分类、申请总数量、参考总金额。金额按申请提交时备件主数据的参考单价乘申请数量计算；未维护价格的备件按零参与汇总。

未命中流程条件时，系统记录“未命中审批条件，系统自动放行”，领用单直接进入待拣货。命中后按配置节点顺序串行流转。

审批记录保存流程版本和条件判定说明，包括申请分类、申请总数量、参考总金额、配置阈值以及采用“任一满足”或“全部满足”的结果。未配置启用流程时同样保存系统自动放行记录。

## 申请人身份自动通过

当节点指定用户就是申请人，或者节点指定角色等于申请人当前角色时，系统自动完成该节点，并写入审批人、处理时间和“系统自动通过”意见。之后继续寻找下一节点；所有节点均自动通过时业务直接进入审批完成状态。

人工审批仍禁止申请人处理自己的待办。管理员只能对真实待办兜底，不能覆盖已经由系统自动完成的节点。

## 状态流转

### 领用与出库

PENDING_APPROVAL → APPROVED → PICKING → DONE。审批驳回进入 REJECTED，可由原申请人或管理员重新提交；未完成业务可以取消。DONE 时间同时作为备件安装时间和开始使用时间。

### 退库

从 DONE 领用明细发起。提交审批后库存不变；最终通过后重新校验可退数量，增加原库位原批次库存。不得超过已出库数量减累计已退数量。

### 报废

从具体库存记录发起。提交审批后库存不变；最终通过时重新锁定库存并校验数量，扣减库存、生成流水和审计记录。

### 盘点

COUNTING 状态录入实盘数。没有差异时直接进入 DONE；存在差异时进入 PENDING_REVIEW。通过后调整库存并完成，驳回后返回 COUNTING 重新核对。

## 权限关系

页面权限决定能否进入审批中心；页面下按钮权限用于角色能力配置；流程节点的角色或用户配置决定具体任务由谁处理。前端隐藏入口只改善体验，后端会再次校验当前节点分配。
