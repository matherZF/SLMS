# 备品备件全生命周期数字化管理系统项目总览

## 项目定位

系统聚焦备品备件全生命周期，而不是设备全生命周期。以备件数字台账为基础，覆盖主数据、批次、货位、入库上架、领用审批、扫码出库、关联退库、报废、移库、盘点、使用寿命、设备运行数据同步、预警和审计。

## 当前技术基线

| 层次 | 当前实现 |
| --- | --- |
| 前端 | Vue 3、Vite、Pinia、Element Plus、Axios、html5-qrcode |
| 后端 | Java 17、Spring Boot 3.2.5、Spring Security、Spring Data JPA |
| 生产数据库 | MySQL 8.0+，默认数据库 spare_parts，Hibernate update 自动补充结构 |
| 测试数据库 | H2 内存数据库 |
| 设备数据 | 独立只读数据源，查询设备系统开放视图 |
| 访问方式 | 内网 IP；桌面端和移动端共用 API，移动扫码建议 HTTPS |

## 已实现模块

- 备件主数据：分类、编码、规格、单位、品牌、型号、厂家、关键程度、参考单价、库存阈值和寿命指标。
- 仓库货位：一个备件间、货架位置和地面耗材区域，支持货位二维码及定位。
- 入库上架：到货登记、批次信息、库位选择、分批上架、库存及流水同步。
- 领用出库：申请、审批、分配货位、拣货、电子标签按键确认（备件与货位双码核验为可选辅助校验）、确认出库。
- 统一审批：领用申请、退库确认、报废申请、盘点差异复核；串行节点可指定角色或用户。
- 条件审批：领用流程支持分类、总数量和参考总金额，支持始终、任一和全部条件模式。
- 自动审批：申请人与节点指定用户相同，或属于节点指定角色时，系统自动通过并保留记录。
- 退库：严格关联已完成领用明细，限制可退数量，审批后退回原库位和原批次。
- 报废和移库：报废审批后扣减；移库原子更新两个库位并生成成对流水。
- 库存盘点：冻结账面快照，无差异直接完成，有差异审批后调整，驳回后恢复盘点。
- 使用台账：出库确认时间作为安装与开始使用时间，记录设备运行基准、快照和寿命进度。
- 系统管理：用户、动态角色、页面及页面按钮权限、数据字典、流程配置、操作审计。
- 系统提醒：个人审批待办与超时标识、可用库存不足、批次临期/过期和备件寿命预警。

## 业务控制原则

1. 库存不能直接编辑，只能由入库、出库、退库、报废、移库和盘点业务驱动。
2. 库存变化与流水记录处于同一事务。
3. 开始拣货先占用库存，确认出库再扣减实存；取消拣货释放占用，可用库存等于实存减占用。
4. 退库、报废和盘点差异在最终审批通过前不改变库存。
5. 自动审批必须生成审批记录，不能静默跳过。
6. 确认出库前必须收到全部拣货项的电子标签按键回调；备件与货位双码核验为可选辅助校验。重复确认不得二次扣库：携带相同幂等键的重试返回幂等结果，未带键或键不一致的重复提交被拒绝。
7. 设备数据库只读，外部数据失败不得阻断库存主流程。

## 当前限制与后续优化

- 参考金额不是财务结算金额；后续如接入采购价格，应增加价格版本与生效时间。
- 当前流程为单业务一套串行流程，尚不支持同一业务多套规则、并行会签、转办、加签和委托。
- 数据库结构已由 Flyway 管理；V1 为基线结构，后续版本使用增量迁移，Hibernate 仅负责结构校验。
- 入库来源和质量检验字段尚未最终确定，应避免过早固化。
- 序列号管理、附件上传、消息通知、审批超时升级和完整报表体系仍需后续迭代。
- 设备数据目前只使用设备编号、累计运行时长和累计执行任务数，不扩展为设备全生命周期系统。
