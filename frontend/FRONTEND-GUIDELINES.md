# 前端开发基线

## 信息架构

一级区域固定为：工作台、业务作业、数字台账、基础数据、系统管理。新增功能先判断所属区域，禁止直接在侧栏继续堆叠菜单。

## 三端两壳约定

三个部署目标共用两套布局外壳，禁止为单一目标再派生第三套：

| 目标 | 识别方式 | 外壳 |
| --- | --- | --- |
| 桌面 WEB | 非 APP 且视口 ≥ 768px | `DesktopLayout`（现有，不改动） |
| Android APP | `Capacitor.isNativePlatform()` | `AppLayout` |
| 手机浏览器 | 视口 < 768px | `AppLayout`（与 APP 视觉一致） |

- 外壳选择集中在 `App.vue` + `src/composables/usePlatform.js`，页面不得自行判断平台。
- 页面内区分移动/桌面模板统一用 `useMobile()`（已升级为"APP 或窄视口"语义），不再手写 `window.innerWidth`。
- App 端全局样式统一放 `src/styles/app.scss`，根选择器为 `body.app-shell`（App.vue 负责挂类）；不要在页面里写 `.app-shell` 私有样式。
- APP 端交互约定：弹窗即底部动作面板（app.scss 已全局处理）、按钮触控高度 ≥ 44px、顶部/底部留 `env(safe-area-inset-*)`。

## 权限规范

- 权限能力统一维护在 `src/config/permissions.js`。
- 页面通过 `auth.can(...)` 或既有语义属性判断，禁止散落硬编码角色数组。
- `ADMIN`：系统配置、主数据维护以及业务兜底。
- `APPROVER`：审批处理与相关业务查询。
- `WAREHOUSE`：申请、入库、出库、移库、盘点等仓库业务操作。
- `VIEWER`：台账、流水、预警等只读查询。
- 前端隐藏无权操作只是改善体验，后端接口仍必须进行最终鉴权。
- 审批统一使用“审批中心”，不得再把统一入口命名为“领用审批”。业务类型使用“领用申请、退库确认、报废申请、盘点差异复核”。
- 按钮权限必须隶属于页面权限；新增操作时先确定所属页面，禁止创建与页面脱离的按钮权限。

## 页面结构

页面统一使用 `PageHeader + filter-bar + table/card + pagination`。主要操作放在标题操作区或筛选区右侧；同一动作不得同时出现超过两个入口。

## 视觉规范

- 主色使用科技蓝，青色仅用于强调数字化状态；危险操作保持红色。
- 页面使用浅色内容卡片，避免每个业务页面自行定义不同背景。
- 圆角、阴影、表头、输入框和弹窗使用全局样式，页面局部样式只处理自身布局。
- 移动端优先保留当前角色的高频流程，底部导航不超过五项。

## 新功能接入顺序

1. 明确业务归属和允许角色。
2. 在权限矩阵中增加能力（确有新能力时）。
3. 配置菜单或流程入口。
4. 复用公共页面结构与状态样式。
5. 同时检查桌面端、移动端和无权限状态。
6. 完成前运行 `npm run build`。

## 审批与流程页面规范

- 审批中心必须展示业务类型、业务单号、申请人、当前节点、提交时间和等待时长。
- 驳回原因必填；通过操作应说明进入下一节点还是完成业务执行。
- 移动端使用审批卡片，不把桌面宽表格直接压缩到手机宽度。
- 流程配置按“基础信息、触发条件、审批节点”组织；节点支持上移、下移和删除。
- 条件审批中的金额必须明确为参考金额，不得展示为财务结算金额。
- 自动审批节点仍属于审批轨迹，前端不得隐藏其审批意见和处理时间。
